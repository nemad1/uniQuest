Modify and upgrade the Guild Master / Admin interface for the “Downtown” university platform.

Goal:
Update the admin page so it matches the new reward system of the Vanguard student interface. Remove all money, wallet, payment, escrow, deposit, and financial reward elements. Replace them with a points, certificate, badge, leaderboard, and recognition system.

The Admin / Guild Master user should be able to create missions, assign points, review proof, approve student progress, issue certificates, and track student achievements.

Visual Style:
Keep the same design style as the Login Page and Vanguard Page:
- Deep Navy background
- Gold highlights for rewards and certificates
- Cyan accents for tech/status actions
- Emerald accents for approved/completed states
- Glassmorphism cards
- Soft glow effects
- Rounded corners
- Premium university SaaS style
- Subtle gamified RPG feeling
- Professional enough for clubs and university departments

Important:
The admin interface should feel official, trusted, and powerful. It should look like a control center where clubs and university departments can manage student engagement.

Remove These Elements:
- Wallet balance
- Money rewards
- Escrow
- Deposit system
- Payment release
- Financial transactions
- Cash reward labels

Replace Them With:
- Points rewards
- Certificate rewards
- Badge unlocks
- Volunteer hours
- Leaderboard impact
- Official recognition
- Student achievement tracking

Main Admin Dashboard Layout:

Top Section:
Create a Guild Master status header.

Include:
- Admin / Club name
- Role badge: “Guild Master”
- Verified university department badge
- Total active missions
- Total points awarded
- Total certificates issued
- Pending proof reviews

Example:
“Tech Club — Guild Master”
“Verified University Organization”
“12 Active Missions”
“18,420 Points Awarded”
“42 Certificates Issued”
“9 Pending Reviews”

Use gold and cyan highlights.

Section 1: Mission Creation With Points & Certificate Rewards

Create or improve a mission creation panel called:

“Create Recognition Mission”

Fields:
- Mission title
- Mission description
- Mission type: Official Mission / Mentorship Mission / Volunteer Mission / Hackathon Support / Event Support
- Difficulty: Easy / Medium / Hard
- Deadline
- Maximum participants
- Required proof type: Photo / Link / Text Report / File Upload / Mentor Confirmation
- Points reward
- Volunteer hours
- Certificate progress reward
- Badge reward

Reward Setup Options:
Instead of money, allow the admin to select:
- Points only
- Points + certificate progress
- Points + badge
- Points + volunteer hours
- Full certificate unlock

Example reward setup:
Mission: “Guide First-Year Students”
Reward: +150 Points
Certificate Progress: Counts toward Peer Mentor Certificate
Volunteer Hours: +1 Hour
Badge: Junior Support Badge

Add a button:
“Publish Mission”

Important UX Rules:
- Admins should clearly understand that they are rewarding students with points, certificates, badges, and recognition.
- The page should not mention money or payments anywhere.
- The admin should feel in control of campus engagement.
- Proof approval should directly connect to points and certificate progress.
- Certificates should feel official and valuable.
- Keep the dashboard clean, not too crowded.
- Use strong visual hierarchy.
- Use gold for achievements and certificates.
- Use emerald for approved states.
- Use cyan for system actions and analytics.
- Use red only for rejection or warning states.

Microinteractions:
- Hover glow on certificate cards
- Animated points counter
- Smooth approval animation when proof is approved
- Certificate unlock animation
- Rank progression animation
- Campaign progress animation
- Soft card hover movement

Main Dashboard Priority:
1. Admin status summary
2. Pending proof reviews
3. Create mission with points/certificate rewards
4. Certificate approval queue
5. Student achievement dashboard
6. Leaderboard and analytics
7. Recognition campaigns and certificate templates

Final Result:
The Guild Master / Admin interface should become a full recognition control center. Admins should be able to create missions, assign points, approve proof, build certificates, issue certificates, manage campaigns, and track student growth. The design must match the Vanguard interface and show that Downtown rewards students through leadership, contribution, certificates, and campus reputation instead of money.
